# 05 计算复杂度：每次估计的计算量与 CPU 时间

**要回答的问题：** 每估计一个信道向量，各方法要做多少次乘加、存多少个参数、在 CPU 上花多少时间？给报告里的复杂度表，以及汇报中"代价和收益"的对比提供依据。

```bash
python experiments/05_complexity/run_complexity.py --member <名字> --smoke         # 冒烟测试，约 10–20 秒，不保存
python experiments/05_complexity/run_complexity.py --member <名字> --threads 1     # 正式运行：单线程
python experiments/05_complexity/run_complexity.py --member <名字> --threads 4     # 可选：4 线程对照，另存一个结果文件夹
```

联合 MLP 的尺寸定下来以后，用 `--joint-hidden 1024 1024` 这类参数改尺寸再跑。其他参数：`--methods`、`--settings`、`--densities`、`--gmm-k-spacefreq`、`--n-batch`、`--repeats`，见 `--help`。

## 协议

- **不读任何实测数据。** 导频、权重、协方差都是形状正确的合成数据。稠密运算的耗时与数值无关，所以不需要真实数据。
- 这里只测代价、不测精度，所以验证集分块、全局缩放、NMSE 等精度协议在这里用不到。run 0056 和 0057 都不涉及。
- **线程：** `--threads`（默认 1）在导入 numpy 之前写入 `OPENBLAS_NUM_THREADS`。`run.json` 的 config 里记录：
  - 线程数，以及 threadpoolctl 报告的实际 BLAS 线程数；
  - `platform.processor()`；
  - numpy 版本，BLAS 名称和版本。
- **批量吞吐：**
  - 每次重复把 100,000 个向量按每次调用 10,000 个（`--chunk`）送进估计器，先预热一个块；
  - 重复 5 次取中位数，单位是 µs/向量；
  - 某个方法累计超过 300 s 且已经重复 3 次时提前停止；
  - 实际重复次数和每次的数值都记在 metrics 里。
- **单向量延迟：**
  - 批大小为 1，预热 20 次后最多调用 1000 次，每次单独计时，报中位数和 p90；
  - 超过 30 s 且已调用至少 20 次时提前停止；
  - 结果包含 Python 调用开销，这正是小矩阵方法的主要开销。
- 计时期间关闭垃圾回收（gc）。
- **建议的运行条件：**
  - 接上电源，Windows 电源模式选"最佳性能"；
  - 关掉其他程序，尤其是训练任务；
  - 这颗 CPU 有 P 核和 E 核，单线程可能被调度到 E 核上，最好跑两次核对数字是否一致。
- **负载自检：** 批量计时同时记录进程 CPU 时间（`batch_cpu_s`）和墙钟时间（`batch_wall_s`）。
  - 单线程时两者之比应接近 1；
  - 墙钟时间至少 2 s、比值却低于 0.85 的方法，会在运行结束时打印警告，并写进 `config.timing_warnings`。这说明进程被别的任务抢占，这些数字偏大，应在空闲时重跑；
  - Windows 的进程 CPU 时钟每 15.6 ms 才跳一次，所以只有墙钟时间不少于 1 s 时，日志里才打印这个比值。

## 方法

主线：单天线，64 个子载波，16 / 8 / 4 个导频，估计其余子载波。

| 代号 | 方法 | 用到的代码 |
|---|---|---|
| `linear` | 线性插值，稠密矩阵 `Y @ W.T` | `estimators.linear_matrix`，与 experiments/01 相同 |
| `spline` | 三次样条，稠密矩阵 `Y @ W.T` | `estimators.spline_matrix` |
| `lmmse` | LMMSE，按一个假设的 SNR 预先算好 G | `LMMSE.matrix` / `LMMSE.apply` |
| `lmmse_ps` | LMMSE，每个向量用自己的噪声方差（特征分解形式） | `LMMSE.apply_per_sample` |
| `mlp` | MLP 2×128，输入 2P+1，输出 2M | `neural.make_predictor("mlp")`，尺寸同 `VARIANTS` 和 run_mlp.py |
| `residual` | LMMSE + 残差 MLP 2×128 | `neural.make_predictor("residual")` |
| `gmm` | GMM 估计器，按现有实现，K=16 | `gmm_feasibility.mix_estimate` |
| `gmm_pre` | 同一个 GMM 估计器，各分量矩阵全部预先算好，只计在线部分 | 本文件的 `gmm_precompute` / `gmm_pre_apply` |

天线 × 频率联合设置（experiments/03 的 spacefreq）：32 根天线 × 16 个子载波，共 512 维。导频分两种：32 根天线 × 4 个子载波（128 个），以及 8 根天线 × 4 个子载波（32 个）。

| 代号 | 方法 |
|---|---|
| `joint_lmmse` | 用完整 512×512 协方差的 LMMSE，G 预先算好 |
| `joint_lmmse_ps` | 同上，但每个向量用自己的噪声方差（`apply_per_sample`），即 experiments/07 中 `jresidual` 的基线部分 |
| `joint_mlp` | MLP [2P+1, 512, 512, 2M]，即 experiments/07 的 `jmlp`（尺寸是占位，可用 `--joint-hidden` 修改） |
| `joint_residual` | 同一个 MLP 加上逐样本联合 LMMSE，即 experiments/07 的 `jresidual` |
| `gmm`、`gmm_pre` | K = 16 和 64 |

- `mlp_blind` 和 `mlp_relweight` 没有单独计时：它们的网络结构与 `mlp` 相同，计算量也相同。
- `mlp_wide`（3×256）没有默认计时。解析值为 (2P+1)·256 + 2·256² + 256·2M = **164,096** 次实数乘加，与导频数无关。需要实测时可以加跑一次：`--settings freq64 --methods mlp --mlp-hidden 256 256 256`。

## 计数规则

- 矩阵乘法、逐元素缩放、内积中的每一次乘法都算一次**乘加（MAC）**。
  - 复数 × 复数：1 次复数乘加，等于 4 次实数乘加。
  - 复数 × 实数：2 次实数乘加。
  - 实数 × 实数：1 次实数乘加。
- 表中"复数乘加"一律等于实数乘加 ÷ 4。对 MLP 这种实数运算，它是"复数等效"值。
- **实矩阵乘复数据（插值的 `Y @ W.T`）按复数 × 复数计**：numpy 会先把实矩阵提升为复数，再调用 zgemm，这就是"实现"的真实计算量。
- **逐元素的乘、除按算术代价计**（复数 × 实数 = 2 次实数乘加）。numpy 的逐元素运算其实也会先提升类型，所以"实现"列对逐元素部分略有低估：每个 GMM 分量最多少计 d/2 次复数乘加，其他方法更少。
- 不计：
  - 没有乘法的加减（减均值、加偏置、求和）、ReLU、exp、log；
  - GMM 后验权重归一化的 K 次除法；
  - MLP 输入特征 snr/30 的缩放，以及输出拼回复数时乘 1j 的那一步。
- 不计离线一次性的工作：求 G、特征分解、EM、训练。
- `mix_estimate` 每次**调用**都会重建逆矩阵。这部分单独列为"每次调用的开销"：
  - 它计入延迟；
  - 批量吞吐时，它分摊到一个块的 10,000 个向量上。
- **存储参数**：在线估计需要的实数个数。一个复数算 2 个实数。
- **"实现"与"最少"**：
  - "实现"按现有代码的写法计数；
  - "最少"是同一个估计结果的最省写法（只算被估计的 M 个位置、利用稀疏或三角结构）；
  - 两者相同时，表中记为"—"。

**自检：** 脚本每次启动都会运行 `check_formulas`。它在几组小尺寸上运行"带计数的重新实现"，覆盖 5 组主线尺寸（含 n=20、13 的非均匀导频）和 3 组小 GMM，共 65 个情形，要求：
1. 数出的乘加次数等于公式；
2. 重新实现的输出等于被计时的实现。

任何一项不符就报错退出，结果记在 `run.json` 的 `config.formula_check` 里。另外两个硬性检查：
- MLP 2×128 在 16 个导频时为 33·128 + 128·128 + 128·96 = 32,896 次实数乘加（`check_formulas` 内）；
- 每个被计时的 GMM 模型（包括 d=512、K=64），在计时前用前 8 个向量比较 `gmm_pre` 与 `mix_estimate` 在被估计位置上的输出，最大相对误差必须小于 1e-9，否则报错退出。每个模型的误差也记在 `config.formula_check` 里。

## 公式推导（每次估计）

记号：
- d：向量长度，主线为 64，联合设置为 512；
- P：导频数；
- M = d − P：要估计的位置数；
- K：GMM 分量数。

**1. 线性插值、三次样条（实现）：** `Y @ W.T`，W 是 d×P 的实矩阵。
- numpy 会先把 W 提升为复数，再调用复数矩阵乘法，所以是 **dP** 次复数乘加。存储 dP 个实数。
- **线性插值最少：** 每个被估计的子载波只用左右两个导频，2 个实权重乘复数，即 2M 次"复 × 实"。合计 **4M 次实数乘加（M 次复数等效）**，存储 2M 个权重。
- **样条最少：** 取下面两种写法中较省的一种：
  1. 只算 M 行：MP 次"复 × 实"，即 2MP 次实数乘加。
  2. 局部写法，合计 2(6P − 14 + 4M) 次实数乘加：
     - 用三抽头公式算右端项：3(P−2) 次；
     - 用预先分解好的 Thomas 递推解 P−2 个内点的二阶导数：3(P−2) − 2 次；
     - 每个被估计点用 4 个抽头求值：4M 次。

  16 和 8 个导频时局部写法更省，4 个导频时只算 M 行更省。

**2. LMMSE，预先算好 G（`LMMSE.apply`）：** 计算 μ + G(y − μ_P)，G 是 d×P 的复矩阵。
- 实现：**dP** 次复数乘加。存储 G 和 μ，共 2dP + 2d 个实数。
- 最少：只算 M 行，并把均值折进偏置 μ_M − G_M μ_P，共 **MP** 次。存储 2MP + 2M 个实数。
- 离线代价是每个假设的 SNR 解一次 P×P 线性方程组。
- 在线计算量与插值相同，都是一次 d×P 的矩阵乘法。

**3. LMMSE，逐样本噪声方差（`apply_per_sample`）：** 三步：
1. z = Uᴴ(y − μ_P)：P² 次；
2. z 逐元素除以 (λ + ρ·ppow + σ²)：P 次"复 ÷ 实"，按 P/2 次复数乘加计；
3. μ + A z，其中 A = C[:,P] U：dP 次。

- 合计 **P² + P/2 + dP**；最少（只算 M 行）为 P² + P/2 + MP。
- 存储 μ、λ、U、A 和常数 ρ·ppow，共 2d + P + 2P² + 2dP + 1 个实数。
- 比固定 G 多出 P² + P/2：这是"每个样本使用自己的 SNR"的代价。

**4. MLP：** 实数乘加 Σ aᵢbᵢ，aᵢ、bᵢ 是相邻两层的宽度。存储 Σ (aᵢ + 1) bᵢ 个实数。
- 2×128 为 (2P+1)·128 + 128·128 + 128·2M。
- 因为 P + M = 64，结果恒为 128·129 + 16384 = **32,896**，与导频数无关。
- 输入特征 snr/30 的一次缩放不计入。

**5. LMMSE + 残差 MLP：** MLP 加上逐样本 LMMSE。按现有实现，LMMSE 先算全部 d 个位置，再取被估计的 M 个，所以 LMMSE 部分是 P² + P/2 + dP。

**6. GMM，按现有实现（`mix_estimate`）：**
- **每次调用的重建开销：** 对每个分量建 S_k = C_k[P,P] + σ²I，然后：
  - 求逆两次：一次用于 G_k，一次在 `logpdf` 里，每次基于 LU，约 4P³/3；
  - 求一次 slogdet，约 P³/3；
  - 计算 G_k = C_k[:,P] S_k⁻¹，dP² 次。

  合计约 **K(dP² + 3P³)** 次复数乘加。
- **每个向量：** 每个分量要做下面这些运算，合计 **K(P² + P + dP + d/2)**：
  - `logpdf` 里的 yᴴS_k⁻¹：P² 次；
  - 再与 y 逐元素相乘：P 次；
  - G_k y：dP 次；
  - 后验权重乘以估计值：d 次"复 × 实"，即 d/2 次。
- **存储：** π 和全部 K 个 d×d 协方差，共 K + 2Kd² 个实数。K=64、d=512 时为 3,355 万个实数，用 complex128 存是 268 MB。

**7. GMM，预先算好（`gmm_pre`）：**
- **离线：** 对每个分量做 Cholesky 分解 S_k = L_k L_kᴴ，存三样东西：
  - L_k⁻¹；
  - B_k = C_k[M,P] S_k⁻¹；
  - log π_k − log det S_k。
- **在线，每个分量：**
  - w = L_k⁻¹ y：P² 次，利用下三角结构最少 P(P+1)/2 次；
  - yᴴS_k⁻¹y = |w|²：P/2 次；
  - 权重乘 y：P/2 次；
  - B_k(权重·y)：MP 次。

  实现共 **K(P² + P + MP)**，最少为 **K(P(P+1)/2 + P + MP)**。
- **存储：** K(2P² + 2MP + 1) 个实数。L⁻¹ 的对角为实数，所以三角存储最少为 K(P² + 2MP + 1)。
- 它与 `mix_estimate` 在被估计位置上的数值一致（自检）。
- **单位分量代价约等于一次 LMMSE**，所以 GMM 约为 LMMSE 的 K 倍。

**8. 联合 LMMSE：** 同第 2 条，d = 512。

**9. 联合 MLP [2P+1, 512, 512, 2M]：** 512·(2·512 + 1) + 512² = **786,944** 次实数乘加。128 个和 32 个导频时相同。

**10. 联合 LMMSE（逐样本）与联合残差 MLP：** 分别同第 3 条和第 5 条，d = 512。代码路径与主线完全相同（`apply_per_sample`、`make_predictor("residual")`），只是维度不同。

从解析计数可以直接看出：
- **按现有写法，三种传统估计器的在线代价相同**，都是一次 d×P 的矩阵乘法。LMMSE 多出的代价只在离线（估计协方差、解方程）。按最少写法，插值便宜得多（16 个导频时线性插值 48 次复数等效乘加，LMMSE 768 次）。
- **MLP 2×128 的代价与导频数无关**：16 个导频时约为 LMMSE 的 8 倍，4 个导频时约为 32 倍。
- **GMM 约为 LMMSE 的 K 倍**。experiments/03 README 中估计的"K=16 约 20–30 倍"：
  - 按现有写法是 20 倍，另加每次调用的重建开销；
  - 预先算好后是 16 倍。
- **512 维、K=64 时 GMM 存储量很大**：按现有写法要存 3,355 万个实数，预先算好后最少也要 734 万个。联合 MLP 2×512 只有约 79 万个参数。

## 预计运行时间与内存

- **冒烟测试：** 约 10–20 秒。这是 2026-11-26 在 Intel Core Ultra 5 125H 上、1 或 2 个线程、机器高负载时实测的。
- **正式运行（单线程）：** 约 30–60 分钟。
  - 这个数是按上面的公式和 8–15 G 实数乘加/秒推算的，没有实测。
  - 大部分时间花在 512 维、K=64 的 GMM 上，其余方法合计不到 8 分钟（其中 `joint_lmmse_ps` 和 `joint_residual` 约 1–3 分钟）。
  - 用 `--threads 4` 会更快。
  - 想缩短时间，可以加 `--n-batch 20000`：每个向量的耗时与向量总数无关。
- **内存峰值约 1 GB：**
  - K=64 的 64 个 512×512 复协方差，268 MB；
  - 100,000 × 128 的输入，205 MB；
  - 每块的临时数组。

`results/<时间>_<成员>_complexity/`，内容：

  - metrics 的键形如 `freq64/16/lmmse`、`spacefreq/128/gmm_k64_pre`；

## 结果

三次运行，全部在 Intel Core Ultra 5 125H、单 BLAS 线程上：

| 结果文件夹 | 条件 | 用途 |
|---|---|---|
| `results/20261126-1954_auto_complexity` | 未固定核心，全部方法 | 已被取代 |
| `results/20261126-2006_auto_complexity` | 未固定核心，只重测 32 导频的两行 GMM K=64 | 已被取代 |
| `results/20261126-2031_auto_complexity` | `--cpu 0`（固定在逻辑处理器 0、高优先级），`--n-batch 20000` | 暂用；机器空闲时还要重测 |

**为什么固定核心。** 这颗 CPU 混合了快核和慢核。单线程测试按核心逐个固定后，逻辑处理器 0 一次 64×64 矩阵乘法测试约 200 ms，其余多数核 400–640 ms。未固定时调度器会把进程在快慢核之间搬动，同一种计算在不同行之间可差 2–3 倍：例如联合 MLP 在 128 和 32 个导频时乘加次数相同，未固定那次测出 128 µs 和 42 µs，固定后是 69.5 µs 和 69.4 µs。GMM K=64 预计算（32 导频）三次分别是 426、770、889 µs。

**这次固定核心的运行也有限制。** 运行期间另一个 16 进程的任务让整机 CPU 负载达到 100%。CPU 0 由本进程以高优先级独占，没有被抢占（所有方法 CPU 时间/墙钟时间约 1.0，`timing_warnings` 为空），但全核满载时芯片降频，所以绝对时间偏慢（线性插值 16 导频：空闲时未固定 0.37 µs，这次 1.58 µs）。同一方法各次重复的范围多数在 10% 以内，个别行在两档之间跳（最大约 1.7 倍，见下表）。

- 64 子载波：插值和 LMMSE 每个向量约 1–2 µs，MLP 约 15 µs，残差 MLP 约 20 µs，预计算的 GMM K=16 约 27 µs。这么小的运算主要是调用和内存开销，时间与乘加次数不成比例。
